4) Environment Variables المطلوبة
----------------------------------
POLLINATIONS_API_KEY
القيمة يجب أن تكون المفتاح فقط. لا تضع echo أو Bearer أو علامات اقتباس.
المسار المجاني الحالي لا يعتمد عليه، لكن يفضل إبقاؤه مضبوطاً للمسارات المدفوعة أو المستقبلية.

GROQ_API_KEY
مطلوب لتحسين Prompt وللدردشة والتحليل حسب إعدادات المشروع.

GEMINI_API_KEY
مطلوب لمسارات Gemini Pro أو fallback الخاصة بالصور.

PAYTABS_PROFILE_ID
PAYTABS_SERVER_KEY
يجب أن يكون PAYTABS_SERVER_KEY هو Standard Web Authentication Key، وليس Mobile Authentication Key.
خطأ PayTabs التالي يدل غالباً على مفتاح Mobile:
Request must be type application/octet-stream

AUREVION_WALLET_ENFORCE
إذا كان true فالدفع يطبق على المهام المدفوعة فقط، ولا يفرض رصيداً على Pollinations المجاني بعد الإصلاح الأخير.

8) ما يحتاج متابعة مستقبلية
----------------------------
أولاً، يجب اختبار طلب إنشاء صورة فعلياً بعد نشر Commit 30c1e27، لأن Groq Prompt Enhancement يعمل فقط في بيئة Production وليس داخل الاختبارات.

ثانياً، إذا كان المطلوب حفظ الصور بشكل دائم داخل قاعدة البيانات أو التخزين، يجب إضافة Object Storage وعدم الاكتفاء برابط Pollinations أو Data URL.

ثالثاً، يجب إضافة اختبار REST كامل لـ /api/chat يتأكد من أن صورة النتيجة تعود في reply وimageUrl.

رابعاً، يجب التحقق من أن إعدادات PayTabs في Vercel تستخدم Profile ID الخاص بنفس الحساب والمنطقة وبنفس Standard Web Key.

خامساً، يمكن لاحقاً تحسين حجم bundle عبر تقسيم Mermaid وCytoscape وWASM إلى dynamic imports.
